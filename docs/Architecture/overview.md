# Архитектура TrayX

## Процессы

```text
TrayX.UI (WPF)  ⇄  Named Pipes  ⇄  TrayX.Core
                                      │
                                      ▼
                     Windows Shell / Audio / Display / Devices
```

`TrayX.UI` отвечает только за интерфейс: окна, настройки, анимации, визуализацию. Он не вызывает напрямую Win32 и не блокируется на системных запросах.

`TrayX.Core` — фоновый процесс: системные события, аудио, устройства, мониторы, конфигурация, интеграция с оболочкой. Падение или зависание Core не должно ронять UI; UI обнаруживает потерю IPC-соединения, но отдельного Watchdog и автоматического перезапуска Core пока нет.

## Слои

| Слой | Проект | Ответственность |
|---|---|---|
| Domain | `TrayX.Domain` | Сущности, value objects, доменные события, правила |
| Application | `TrayX.Application` | Сценарии, команды/запросы, DTO, интерфейсы платформы |
| Contracts | `TrayX.Contracts` | IPC-сообщения, версия протокола, общие DTO границы процессов |
| Infrastructure | `TrayX.Windows`, `TrayX.Storage` | Win32/COM, Core Audio, дисплеи, SQLite, файловые настройки |
| Modules | `TrayX.Modules` | TrayManager, AudioCenter, SoundEvents, QuickSettings, MultiMonitor, SystemMonitor, Automation |
| Presentation | `TrayX.UI` | WPF, MVVM, темы, контролы |
| Host | `TrayX.Core` | DI, запуск модулей, IPC-сервер, логирование |

Зависимости направлены внутрь: Domain не знает об Application, Application не знает о Windows и Storage. Все системные вызовы скрыты за интерфейсами и реализуются в `TrayX.Windows`.

## Совместимость Windows

Сейчас целевая платформа — Windows 11 22H2+ (`net10.0-windows10.0.22621.0`). Ветвления ОС и версионные проверки допускаются только в `TrayX.Windows`. Позже добавляется адаптер для Windows 10 без переписывания Domain и Application. Решение зафиксировано в [ADR-0001](adr/0001-windows-11-first.md).

## Взаимодействие с треем

`Shell_NotifyIcon` управляет только значками, зарегистрированными самим приложением. Полный контроль над чужими значками через публичный API Windows не гарантирован. Поэтому:

- собственные элементы TrayX регистрируются штатно;
- обнаружение и настройка сторонних значков исследуются на этапе 1;
- при отсутствии поддерживаемого API используется безопасная альтернатива;
- недокументированные патчи Explorer, инъекции DLL и правка системных файлов не применяются как основа.

## Производительность

- события Windows там, где они доступны; треевые значки и звуковые события устройств также используют ограниченный polling;
- кэширование иконок и отсутствие повторной загрузки;
- виртуализация списков;
- ограничение частоты обновления мониторинга;
- освобождение COM-объектов и дескрипторов;
- отсутствие блокировок UI-потока;
- защита от дублирования процессов.
