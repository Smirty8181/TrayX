# IPC: TrayX.UI ⇄ TrayX.Core

## Транспорт

Named Pipes. Сервер создаёт канал с `PipeOptions.CurrentUserOnly`, поэтому ОС ограничивает подключение текущим пользователем Windows. Отдельной аутентификации процесса-клиента и handshake протокола нет: другой процесс того же пользователя может обращаться к каналу.

## Контракты

Все сообщения живут в `TrayX.Contracts`. DTO не содержат логику и не зависят от Windows API.

- `TrayXIpc.PipeName` — имя канала, получаемое из идентичности текущего пользователя.
- `TrayXIpc.ProtocolVersion` — версия API, возвращаемая статусом Core и ответом ping; при установке соединения она не проверяется.
- `CoreStatusDto` — состояние ядра для UI.

## Правила

- Envelope содержит тип; запросы и ответы также содержат ID, имя команды и payload. Версии протокола в envelope нет.
- Ответ возвращает результат либо ошибку с текстом; сейчас текст ошибки может содержать подробности исключения.
- События и ответы пишутся одним последовательным worker'ом на соединение; очередь ограничена 128 сообщениями на клиент. При переполнении fire-and-forget события отбрасываются с предупреждением в логе, а доставка ответа/`PublishAsync` ожидает свободного места.
- IPC-клиент использует асинхронный транспорт и ограниченный таймаут ожидания ответа.
- Входная строка ограничена 1 МиБ символов до десериализации. Изображения значков передаются в DTO как Base64, а не через файловый кэш.

## Статус

Named Pipes, IPC-клиент, сервер и маршрутизатор команд реализованы. Watchdog и handshake версии протокола отсутствуют.
