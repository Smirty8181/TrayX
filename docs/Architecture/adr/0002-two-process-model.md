# ADR-0002: Разделение на TrayX.UI и TrayX.Core

- Статус: принято
- Дата: 2026-10-31

## Контекст

Операции с устройствами, аудиосессиями и оболочкой могут занимать сотни миллисекунд и зависеть от состояния драйверов. Выполнение их в UI-процессе приводит к зависанию интерфейса. При этом дробление на отдельный процесс для каждого модуля усложняет обмен данными и увеличивает потребление памяти.

## Решение

Два процесса:

- `TrayX.UI` — WPF, MVVM, только представление и пользовательские сценарии;
- `TrayX.Core` — фоновый процесс со всеми системными интеграциями и модулями.

Связь — Named Pipes через контракты `TrayX.Contracts`. Модули остаются библиотеками внутри Core, а не отдельными процессами.

## Последствия

- UI не блокируется системными вызовами.
- Core можно перезапускать и восстанавливать независимо.
- Появляется IPC-протокол, который нужно версионировать и тестировать.
- Требуется защита от дублирования процессов. Автоматический Watchdog и перезапуск Core пока не реализованы.
