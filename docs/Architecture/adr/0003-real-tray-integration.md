# 0003. Интеграция с настоящим треем Windows 11

Дата: 2026-10-31
Статус: принята

## Контекст

TrayX должен управлять видимостью значков области уведомлений, не подменяя системный трей.
Требования заказчика: никаких патчей Проводника, инъекций DLL и правки системных файлов.
Проверка доступных путей на Windows 11 22631 дала такую картину.

## Что проверено на живой системе

| Путь | Результат |
| --- | --- |
| Классический `ToolbarWindow32` (ButtonN, `TB_BUTTONCOUNT`) | Недоступен: сообщается 0 кнопок, панель собрана на XAML-острове |
| UI Automation (`Shell_TrayWnd`, `Shell_SecondaryTrayWnd`) | Работает: значки панели имеют AutomationId `SystemTrayIcon` |
| Область скрытых значков | Отдельный дочерний хаб `TopLevelWindowForOverflowXamlIsland`, перебирается через `EnumChildWindows`; элементы — `NotifyItemIcon` |
| Реестр `HKCU\Control Panel\NotifyIconSettings` | Доступен: подразделы с 20-значными числовыми ID, значения `UID`, `ExecutablePath`, `InitialTooltip`, `IsPromoted`, `IconSnapshot` (PNG есть у 45 значков из 45) |
| Владелец значка (PID/HWND) | Через UI Automation не публикуется |

## Решение

TrayX читает трей через UI Automation, а закрепление меняет в `NotifyIconSettings.IsPromoted`.
Идентификатор значка строится из индекса монитора, класса элемента и позиции (`live:{монитор}|{класс}|{x}x{y}`):
подсказки меняются каждую минуту (часы, уведомления), поэтому имя в идентификатор не входит — иначе
фоновый опрос генерировал бы ложные события.

Значки, которых нет на панели, берутся из реестра и получают идентификатор `reg:{ключ}`; их статус
(`overflow` / `hidden` / `stale`) определяется по открытости области переполнения и наличию процесса.

## Ограничения, которые мы не прячем

1. Скрытые значки перечислимы только пока открыта всплывающая область; закрытая область уничтожается,
   и `FindWindow` возвращает 0. Список не обновляется «из-за закрытия».
2. Полноэкранное приложение в фокусе (например, игра) подавляет показ области переполнения:
   `Invoke` принимается, но панель не появляется. `ToggleOverflow` возвращает `true`, только если
   состояние реально изменилось.
3. UI Automation не сообщает, какому процессу принадлежит значок, поэтому связка «значок → приложение»
   строится по пути исполняемого файла из реестра и может совпасть с другим процессом того же файла.
4. Изменения `IsPromoted` Проводник подхватывает не сразу: нужен перезапуск `explorer.exe`,
   на несколько секунд скрывающий панель задач. TrayX запускает его по явной кнопке и не делает этого сам.
5. Текст тостов-уведомлений Windows не читается сторонними приложениями через поддерживаемые API:
   TrayX показывает счётчик уведомлений центра, а не их содержимое.
6. Реестр значков принадлежит пользователю: запуск от другого пользователя или из другой сессии
   покажет другой набор.

## Последствия

- Никакой записи вне пользовательского куста реестра и никакого запуска с повышением прав.
- Функции, которым нужен недоступный API, не имитируются: они либо выключаются настройкой,
  либо объясняются в интерфейсе.
- Переключатель «Фоновое чтение реального трея» в настройках отключает сам опрос UI Automation:
  снимок тогда собирается только из реестра, и интерфейс честно помечает это состоянием `live-disabled`.
