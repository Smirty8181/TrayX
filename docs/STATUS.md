## Проверки и история

- `.\scripts\build.ps1` выполняет `dotnet restore`, Release build и тесты решения.
- Исторический результат базовой линии: 16 unit-тестов и 9 integration-тестов; после Audio Center: 19 unit-тестов и 11 integration-тестов.
- Проверка стабильности ID трея теперь сравнивает только повторно обнаруженные элементы на тех же координатах/классе; полное дерево UI Automation закономерно может изменяться между сканами.
- Собственный значок TrayX повторяет регистрацию через оконный таймер при временной ошибке `Shell_NotifyIcon`; интеграционная проверка штатного перезапуска Explorer остаётся ручной.
- Перезапуск Explorer сообщает об ошибке завершения/запуска вместо безусловного сообщения об успехе; проверка фактического восстановления оболочки остаётся ручной.
- Остановка Tray Runtime ожидает polling-задачу и завершение его оконных/UI Automation потоков; при зависшем системном вызове очистка не освобождает ресурсы, используемые ещё живым потоком, и сообщает о таймауте.
- Очередь UI Automation закрывается синхронно с приёмом запросов и выполняет уже поставленные задания до завершения worker-потока.
- P1: идентификатор дисплея передаётся в DTO отдельно от текущего имени `DISPLAYn`; интеграционный тест проверяет его непустоту и уникальность в активной конфигурации.
- Quick Panel содержит системные ссылки Wi-Fi, Bluetooth, авиарежим, настройки приватности камеры/микрофона, питание/экономию энергии, ночной свет, фокус и уведомления; действия и URI перечислены в `docs/QUICK_SETTINGS_MATRIX.md`.
- Settings UI: JSON импорт/экспорт с нормализацией, подтверждением замены/сброса, ограничением входного файла и отказом от будущей версии схемы; сброс не удаляет профили.
- Часы и календарь: пользовательский формат 12/24/системный применён к Quick Panel и панелям мониторов; Quick Panel показывает локализованный календарь месяца, выбранную дату и переход в параметры даты/времени Windows.
- История уведомлений: чтение, сохранение и очистка проходят через одну последовательную очередь; UI повторяет загрузку при новых событиях во время чтения, при возвращении на страницу и после переподключения Core; очистка заблокирована во время загрузки.
- Жизненный цикл Core: ModuleRunner пропускает повторный запуск активного модуля; если запуск отменён, откатывает уже запущенные модули в обратном порядке. Tray Manager освобождает созданные host-потоки при ошибке запуска; Audio Center снимает callback’и при сбое начального чтения. Таймаут остановки Tray Manager, Sound Events или профилей не освобождает ресурсы, пока соответствующий worker ещё работает. При остановке ModuleRunner продолжает после ошибок и сохраняет статус активного модуля с причиной, если остановка не удалась.
- Tray Apps: видимые окна доступны в интерфейсе; ручное скрытие разрешено только для окон, прошедших повторную проверку иерархии/уровня прав. Recovery-запись пишется до `ShowWindowAsync`; восстановление не активирует окно, повторно проверяет процесс и окно, а неподтверждённые записи оставляет в журнале.
- WinEvent монитор Tray Apps использует out-of-context hooks и дебаунс 200 мс; системные callback’и не управляют окнами, а только сигнализируют UI перечитать каталог. Проверена регистрация/очистка hooks интеграционным тестом.
- Последний полный изолированный Release-прогон: 73 unit- и 88 integration-тестов пройдены без предупреждений и ошибок, не перезаписывая файлы запущенных UI/Core.
- IPC: команды получают токен отмены, связанный с жизненным циклом клиента и Core, и ограничиваются 14-секундным таймаутом перед 15-секундным клиентским ожиданием; таймаут логируется, ответ содержит ошибку, подключение закрывается. Остановка сервера ожидается единообразно; клиентские потоки/ресурсы освобождаются, таймауты диагностируются.
- Процессы: все найденные вызовы `Process.Start` освобождают возвращённые process handles после запуска.
- Recovery журнала Tray Apps: при повреждении основного файла восстанавливается проверенная резервная копия, исходный файл сохраняется в карантине; если обе копии непригодны, ошибка явная, обе копии сохранены.
- История уведомлений: число отбрасываемых записей при заполненной очереди учитывается и журналируется; при сбое фонового worker'а очередь закрывается, ожидающие read/clear завершаются ошибками вместо зависания; после штатной остановки повторный запуск создаёт новую рабочую очередь.
- Tray snapshot: единый синхронизированный tracker с порядком сканирования предотвращает устаревшие/повторные уведомления при конкурентных poll- и IPC-вызовах.
- SettingsStore: добавлено атомарное функциональное обновление под семафором, профильные изменения и синхронизация автозапуска используют актуальное состояние; конкурентное сохранение независимых настроек покрыто интеграционным тестом.
- Tray Apps: таймаут regex-правила передаётся в callback и журналируется во время reconciliation; регрессионный тест проверяет timeout.
- SQLite: `quick_check` выявляет повреждение при первой инициализации store; ошибка явная, исходная база сохраняется, покрыто тестами NotificationStore и ProfileStore.
- Tray Apps: каталог исключает owned/tool windows, а стабильная идентичность для hide/restore не зависит от заголовка; регрессии покрывают смену заголовка и фильтрацию типов окон.
- Хранилище: integration tests покрывают CRUD ProfileStore и ограничение истории уведомлений до 1000 записей.
- SettingsStore: integration tests проверяют конкурентное применение независимых изменений, сохранение/повторную загрузку и сохранение повреждённого конфигурационного файла перед восстановлением настроек.
- UI exception log: добавлены ограничение размера, ротация и retention до 14 файлов; покрыто интеграционным тестом.
- Tray panels: периодическое чтение списка дисплеев и brightness выполняется вне WPF Dispatcher; UI-обновление окон маршалится обратно на STA.
- Tray panel icon assets are decoded at monitor-specific DPI sizes and refreshed after effective DPI changes.
- IPC: события каждого клиента отправляются одним sender через FIFO-очередь до 128 сообщений; переполнение диагностируется, последовательность событий покрыта интеграционным тестом.
- Settings validation: IPC rejects configuration versions newer than the supported schema; `Normalize()` validates Tray Apps enum values and bounds collection sizes and individual identifiers/paths.
- Sound preview: only absolute local WAV paths are accepted; UNC, device namespace and mapped remote drives are rejected before invoking WinMM.
- Tray menu notifications now use localized RU/EN text; exception details remain in Core logs while user-facing errors are localized.
- Sound device-change notification now follows Core Audio device callbacks instead of polling every four seconds; event processing is coalesced on a background worker.
- UI accessibility: кнопки-иконки получают AutomationProperties.Name из локализованной подсказки; история уведомлений представлена виртуализированным ListBox с локализованным Automation-именем; избранное аудиоустройств и календарные кнопки используют доступные локализованные подсказки; контраст слабого текста и подписей акцентных кнопок проверяется.
- Физический второй монитор и полный набор реальных аудиоустройств не проверены автоматически.
